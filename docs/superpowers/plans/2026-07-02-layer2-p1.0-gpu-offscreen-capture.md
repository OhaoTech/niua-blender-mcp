# Layer 2 Phase 1 Wave 0 — GPUOffScreen Capture Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** Replace the deferred-transform render path (`render.opengl(view_context=False)` reading a
stale `cam.matrix_world`) with a deterministic `GPUOffScreen.draw_view3d` render fed a
**pure-Python-computed view matrix**, so every eye (`feedback.capture`/`capture_views`/`turntable`/
`topology`/`silhouette`) renders correct, distinct multi-angle images. This is the prerequisite fix
for all form perception. Root cause + verified fix: `docs/reports/capture-multiangle-bug.md`.

**Architecture:** `core/capture.py` gains an offscreen renderer. The framing math (`view_camera`/
`orbit_camera`) already returns `location`/`rotation_euler`/`ortho_scale`/`type` — the view matrix
is computed from THAT (never from `cam.matrix_world`, which is deferred and stale in a single bridge
call). Projection uses `cam.calc_matrix_camera(depsgraph, x, y)` (camera DATA updates immediately).
Rendering uses `gpu.types.GPUOffScreen.draw_view3d(...)` with viewport overlays OFF. All existing
callers keep working because the change is internal to the render step.

**Verified prototype (the canonical reference — READ IT):**
`/tmp/claude-1000/-home-frankyin-Desktop-lab-lab-niua-blender/b9bb9dd1-6c26-4913-8aab-2c600d1478d0/scratchpad/gpu_offscreen_probe2.py`
— proven live: cone front→triangle, top→circle, 4/4 distinct. Includes a working pure-Python PNG
encoder from a GPU UBYTE buffer (bottom-up row flip).

## Global Constraints

- Standalone repo; `from __future__ import annotations`.
- Compute the view matrix in PURE PYTHON from the frame dict:
  `(mathutils.Matrix.Translation(loc) @ mathutils.Euler(rot,'XYZ').to_matrix().to_4x4()).inverted()`.
  NEVER read `cam.matrix_world` for the render transform.
- Render via `GPUOffScreen.draw_view3d(scene, view_layer, space, region, view_matrix, proj_matrix,
  do_color_management=False)`; needs a live VIEW_3D `space` + WINDOW `region` (GUI). No VIEW_3D / no
  GL → graceful `{"available": False, "reason": ...}` (unchanged contract).
- Disable `space.overlay.show_overlays` during capture and RESTORE it (prototype omitted this; the
  gizmo/3D-cursor must not appear in captures).
- Set `space.shading.type` per requested mode and RESTORE: `SOLID` for form/beauty/silhouette;
  `MATERIAL` (or `RENDERED`) for the topology/silhouette emission-material fills. Verify emission
  colours actually show under the chosen viewport shading (LIVE check — see acceptance).
- Preserve the read-only contract and all existing return envelopes/field names.
- Keep the pure framing math (`view_camera`/`orbit_camera`/`bbox_*`) unit-testable under fake-bpy.

## Tasks

### Task 1: Pure-Python view-matrix helper + unit test
- Add `view_matrix_from_frame(frame) -> 4x4` and `projection_is_ortho(frame)` helpers to
  `core/capture.py` (pure math; use `mathutils` with the tuple fallback pattern already in the file).
- Unit-test under fake-bpy: front vs top frames yield DIFFERENT view matrices; a known frame yields
  the expected matrix (compare to a hand-computed value). This is the deterministic core the whole
  fix rests on.

### Task 2: The offscreen renderer
- Add `_render_offscreen(bpy, frame, shading, res) -> str` (base64 PNG) implementing the verified
  prototype: locate VIEW_3D space+region, set overlays off + shading, `GPUOffScreen(res,res)`,
  compute view matrix via Task 1, projection via `cam.calc_matrix_camera` (set `cam.data.type`/
  `ortho_scale` from the frame first), `draw_view3d`, read pixels, PNG-encode (port the prototype's
  encoder), restore overlays/shading, `offscreen.free()`. Graceful-degrade on any failure.
- Rewire `_render_to_b64` (or the callers) so `render`/`capture_views`/`turntable` use
  `_render_offscreen` with the frame (they currently apply a frame to a cam then call
  `_render_to_b64`; pass the frame through instead).
- Keep a headless envelope smoke (`available: False` with no GL) green.

### Task 3: Point the overlay + silhouette eyes at the new path
- `core/overlay.py` (topology) and `core/silhouette.py` render through the same offscreen path with
  their emission materials + `MATERIAL` shading. Confirm the two topology passes (facetype vs
  wireframe-modifier) remain distinct under the new renderer.
- Full suite green; parity holds.

## Acceptance (LIVE — controller-run, needs restart to reload addon)

- `feedback.capture` front≠top; a cone's front renders a triangle and top a circle (Read the PNGs).

- `feedback.topology` → facetype (coloured quads/tris/ngons) and wireframe passes distinct and readable.
